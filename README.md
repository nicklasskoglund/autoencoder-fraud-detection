# Autoencoder Fraud Detection

A small end-to-end machine learning project detecting credit card fraud with an
autoencoder trained **only on legitimate transactions**, treating fraud as an
anomaly-detection problem rather than a classification problem.

## Overview

Fraudulent transactions make up just 0.17% of the dataset — far too few and too
varied to reliably learn as a "class" in a traditional classifier. Instead, this
project trains an autoencoder to reconstruct *legitimate* transaction patterns.
Transactions the model struggles to reconstruct (high reconstruction error) are
flagged as potential fraud.

## Dataset

[Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud)
(Kaggle, `mlg-ulb/creditcardfraud`):
- 284,807 transactions, 492 labeled fraud (~0.17%)
- 28 PCA-transformed features (`V1`–`V28`), plus `Time` and `Amount` (not transformed)

## Approach

The project follows a CRISP-DM-style pipeline, split into four notebooks:

| Notebook | Purpose |
|---|---|
| `01_eda.ipynb` | Explore the data, identify quality issues (1,081 duplicate rows) and class imbalance |
| `02_data_preparation.ipynb` | Remove duplicates, stratified train/test split, scale `Time`/`Amount`, isolate legitimate transactions for training |
| `03_model_training.ipynb` | Train a Dense autoencoder (30→14→7→14→30) on legitimate transactions only; determine an anomaly threshold from validation reconstruction error (95th percentile) |
| `04_evaluation.ipynb` | Evaluate the trained model on a held-out test set (never touched before this step); confusion matrix, classification report |

## Results

Evaluated on a held-out test set (56,746 transactions, 95 fraud):

| Metric | Value |
|---|---|
| Recall (fraud) | 81.05% (77 / 95 caught) |
| Precision (fraud) | 2.61% |
| F1-score (fraud) | 0.0505 |
| Accuracy | 94.90% |

**Note on accuracy:** with 99.83% of transactions legitimate, a model that always
predicts "legitimate" would already score 99.83% accuracy while catching zero
fraud. Accuracy is not a meaningful metric here — recall and precision on the
fraud class are what matter.

The model catches the large majority of fraud without ever seeing a single
fraudulent example during training, at the cost of a high false-positive rate
— the expected trade-off for this approach, which in practice would be paired
with a second filtering step to confirm flagged transactions.

## Setup

```bash
git clone https://github.com/nicklasskoglund/autoencoder-fraud-detection.git
cd autoencoder-fraud-detection

python -m venv .venv
source .venv/Scripts/activate   # Windows Git Bash
pip install -r requirements.txt
```

Download `creditcard.csv` from
[Kaggle](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud) and place it
at `data/raw/creditcard.csv`.

Run the notebooks in order, `01` through `04`. Note: re-running
`03_model_training.ipynb` will retrain the model and may produce slightly
different loss/threshold values due to CPU floating-point non-determinism in
TensorFlow (see the notebook's summary for details) — `04_evaluation.ipynb`
always reads whatever model is currently saved to `models/`.
